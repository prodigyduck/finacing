# Feature Specification: Toss-Style UI/UX Enhancement

**Feature Branch**: `004-toss-style-ui`

**Created**: 2026-06-06

**Status**: Draft

**Input**: User description: "대시보드 UI/UX를 토스 스타일로 개선 - 카드 디자인, 색상 팔레트, 레이아웃 최적화"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 계좌 카드 시각적 개선 (Priority: P1)

사용자는 대시보드를 열었을 때 각 계좌의 정보가 토스 스타일의 카드로 표시되는 것을 보고, 직관적이고 아름다운 디자인으로 자산 현황을 한눈에 파악할 수 있어야 한다.

**Why this priority**: 사용자가 가장 먼저 접하는 UI 요소이며, 시각적 개선이 사용자 경험에 직접적인 영향을 미친다. 토스 스타일의 카드 디자인은 사용자에게 친숙하고 신뢰감을 주는 디자인 언어이다.

**Independent Test**: 카드 디자인만 변경하여 사용자가 개선된 카드를 보고 시각적 향상을 느끼는지 테스트할 수 있다.

**Acceptance Scenarios**:

1. **Given** 대시보드 페이지에 접속했을 때, **When** 페이지가 로드되면, **Then** 각 계좌 카드가 둥근 모서리(16px), 그림자 효과, 배분 비율 원형 프로그레스와 함께 표시된다
2. **Given** 계좌 카드를 보고 있을 때, **When** 계좌명을 읽으면, **Then** 18px Bold 폰트로 명확하게 식별할 수 있다
3. **Given** 계좌 카드를 보고 있을 때, **When** 배분 비율을 확인하면, **Then** 원형 프로그레스로 시각화되어 직관적으로 이해할 수 있다

---

### User Story 2 - 색상 팔레트 통합 (Priority: P2)

사용자는 대시보드 전체에서 토스 스타일의 색상 팔레트(차축, 차순, 기본)가 일관되게 적용된 것을 보고, 브랜드 정체성과 시각적 통일성을 느껴야 한다.

**Why this priority**: 색상은 브랜드 인식과 사용자 경험에 중요한 영향을 미치지만, 카드 디자인보다는 낮은 우선순위이다.

**Independent Test**: 색상 팔레트만 변경하여 사용자가 색상 변경을 인지하고 만족도를 평가할 수 있다.

**Acceptance Scenarios**:

1. **Given** 대시보드를 보고 있을 때, **When** 전체 페이지를 스캔하면, **Then** 토스 스타일 색상 팔레트(차축: #00BFFF, 차순: #FF6B6B, 기본: #F5F5F5)가 일관되게 적용된 것을 확인할 수 있다
2. **Given** 계좌별 그래프를 보고 있을 때, **When** 각 계좌의 선 색상을 확인하면, **Then** 토스 스타일 색상 팔레트를 따르는 것을 확인할 수 있다
3. **Given** 금액 변화를 보고 있을 때, **When** 증감을 확인하면, **Then** 증가는 빨간색, 감소는 파란색으로 구분되어 표시된다

---

### User Story 3 - 레이아웃 최적화 (Priority: P3)

사용자는 대시보드에서 계좌 카드가 상단에 가로 배치되고 그래프가 하단에 크게 표시되는 것을 보고, 정보를 효율적으로 스캔하고 중요한 데이터에 집중할 수 있어야 한다.

**Why this priority**: 레이아웃은 정보 전달의 효율성에 영향을 미치지만, 디자인 요소보다 낮은 우선순위이다.

**Independent Test**: 레이아웃만 변경하여 사용자가 정보를 더 쉽게 찾는지 테스트할 수 있다.

**Acceptance Scenarios**:

1. **Given** 대시보드를 열었을 때, **When** 페이지 상단을 보면, **Then** 계좌 카드가 가로로 배치되어 모든 계좌를 한눈에 확인할 수 있다
2. **Given** 계좌 정보를 확인한 후, **When** 페이지 하단으로 이동하면, **Then** 계좌별 추이 그래프가 크게 표시되어 변동을 명확히 볼 수 있다
3. **Given** 전체 페이지를 보고 있을 때, **When** 각 요소 간의 간격을 확인하면, **Then** 충분한 공백(padding 24px)으로 쾌적한 시각 경험을 제공한다

---

### Edge Cases

- **계좌가 10개 이상인 경우**: 카드 레이아웃이 어떻게 처리되는가? (가로 스크롤, 페이지네이션, 또는 그리드 확장)
- **모바일 화면인 경우**: 카드 배치가 세로로 변경되는가? (반응형 디자인 고려)
- **계좌명이 매우 긴 경우**: 텍스트가 어떻게 처리되는가? (줄임표, 말줄임표, 또는 텍스트 축소)
- **배분 비율이 0%인 계좌인 경우**: 원형 프로그레스가 어떻게 표시되는가? (빈 원형 또는 0% 텍스트)
- **색맹 사용자인 경우**: 색상 외에 다른 시각적 구분 요소가 제공되는가? (패턴, 아이콘, 또는 텍스트 라벨)

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 각 계좌 카드에 둥근 모서리(16px)와 그림자 효과를 적용해야 한다
- **FR-002**: 시스템은 계좌명을 18px Bold 폰트로 표시해야 한다
- **FR-003**: 시스템은 각 계좌의 배분 비율을 원형 프로그레스로 시각화해야 한다
- **FR-004**: 시스템은 토스 스타일 색상 팔레트를 전체 페이지에 일관되게 적용해야 한다 (차축: #00BFFF, 차순: #FF6B6B, 기본: #F5F5F5)
- **FR-005**: 시스템은 금액 증감을 색상으로 구분해야 한다 (증가: 빨간색, 감소: 파란색)
- **FR-006**: 시스템은 계좌 카드를 페이지 상단에 가로로 배치해야 한다
- **FR-007**: 시스템은 계좌별 추이 그래프를 페이지 하단에 크게 표시해야 한다
- **FR-008**: 시스템은 각 UI 요소 간에 24px의 패딩을 제공해야 한다
- **FR-009**: 시스템은 모바일 화면에서 카드 배치를 세로로 변경해야 한다
- **FR-010**: 시스템은 긴 계좌명을 적절히 처리해야 한다 (최대 20자, 초과 시 말줄임표)

### Key Entities

- **계좌 카드**: 계좌명, 총액, 배분 비율, 증감액을 표시하는 UI 컴포넌트
- **원형 프로그레스**: 배분 비율을 시각화하는 원형 차트 컴포넌트
- **색상 팔레트**: 토스 스타일 색상 세트 (차축, 차순, 기본, 증감)

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자의 90%가 개선된 카드 디자인을 "명확하다" 또는 "매우 명확하다"고 평가한다
- **SC-002**: 사용자가 계좌 정보를 찾는 데 걸리는 시간이 30% 이상 단축된다 (기존 평균 5초 → 3.5초 이하)
- **SC-003**: 사용자의 85%가 색상 팔레트를 "일관적이다" 또는 "매우 일관적이다"고 평가한다
- **SC-004**: 사용자의 80%가 레이아웃을 "정돈되었다" 또는 "매우 정돈되었다"고 평가한다
- **SC-005**: 모바일 사용자의 70%가 모바일 레이아웃을 "사용하기 쉽다" 또는 "매우 사용하기 쉽다"고 평가한다

## Assumptions

- 사용자는 토스 앱을 사용해 본 경험이 있으며 토스 스타일의 디자인에 익숙하다
- 사용자는 데스크톱(1920x1080 이상) 또는 모바일(375px 이상) 화면을 사용한다
- 색상 팔레트는 토스의 공식 디자인 가이드를 따른다
- 계좌 수는 최대 10개까지 지원한다
- 배분 비율은 0% ~ 100% 범위를 가진다
- 증감은 전일 대비 비교를 기준으로 한다
