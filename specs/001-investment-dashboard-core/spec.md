**기능 브랜치**: `001-investment-dashboard-core`

**생성일**: 2026-05-31

**상태**: 초안

**입력**: 사용자 설명: "현재 만들어져 있는 기능을 상세히 명세하자. 앞으로는 이 명세를 기반으로 TDD red/green/refactoring 개발을 할거니까"

## 사용자 시나리오 및 테스트

### 사용자 스토리 1 - 포트폴리오 기록 조회 (우선순위: P1)

로컬 마크다운 파일에서 투자 데이터를 읽어 시각화해야 합니다.

**이 우선순위를 선택한 이유**: 투자 트렌드 파악이라는 핵심 가치 제공.

**독립적 테스트**: 올바른 `투자.md` 파일을 제공하고 API를 호출하여 파싱된 기록이 파일 내용과 일치하는지 확인합니다.

**수락 시나리오**:

1. **Given** 구성된 경로에 올바른 `투자.md` 파일이 있을 때, **When** 대시보드를 로드하면, **Then** 과거 포트폴리오 가치가 차트에 표시됩니다.
2. **Given** 데이터 형식이 잘못된 `투자.md` 파일이 있을 때, **When** 대시보드를 로드하면, **Then** 사용자에게 오류 메시지가 표시됩니다.

---

### 사용자 스토리 2 - 추세 분석 및 예측 (우선순위: P2)

과거 추세를 기반으로 향후 포트폴리오 가치를 파악합니다.

**이 우선순위를 선택한 이유**: 과거 데이터에 향후 전망을 추가하여 데이터 가치를 높입니다.

**독립적 테스트**: 과거 데이터 포인트를 사용하여 3, 6, 12개월 예측에 대한 선형 회귀 결과를 검증합니다.

**수락 시나리오**:

1. **Given** 최소 3개월 이상의 과거 데이터가 있을 때, **When** 추세 분석을 요청하면, **Then** 시스템이 3, 6, 12개월에 대한 예측치를 계산하여 반환합니다.
2. **Given** 과거 데이터가 충분하지 않을 때, **When** 추세 분석을 요청하면, **Then** 시스템이 분석을 수행할 수 없음을 알립니다.

---

### 예외 케이스

- Obsidian 파일이 비어 있거나 누락된 경우 어떻게 됩니까?
- 데이터의 날짜 간격이 불규칙한 경우 시스템은 어떻게 처리합니까?
- 포트폴리오 가치가 0이거나 음수인 경우 시스템은 어떻게 처리합니까?

## 요구사항

### 기능적 요구사항

- **FR-001**: 시스템은 로컬 Obsidian 마크다운 파일에서 투자 데이터를 파싱해야 합니다.
- **FR-002**: 시스템은 투자 기록의 형식(`YY.MM.DD 억`)을 검증해야 합니다. (연도 포함 형식으로 변경)
- **FR-003**: 시스템은 총 수익률과 총 변동액을 계산해야 합니다.
- **FR-004**: 시스템은 과거 데이터를 기반으로 선형 회귀 분석을 수행하여 향후 값을 예측해야 합니다.
- **FR-005**: 시스템은 REST API 엔드포인트를 통해 분석 결과를 노출해야 합니다.

### 핵심 엔티티

- **InvestmentRecord**: 포트폴리오 가치의 단일 스냅샷을 나타냅니다 (날짜, 금액).
- **PortfolioHistory**: 분석 결과(총 변동액, 수익률, 예측값)가 포함된 InvestmentRecord의 집합입니다.

## 성공 기준

### 측정 가능한 성과

- **SC-001**: API는 최대 1000개의 레코드에 대해 500ms 이내에 과거 및 예측 데이터를 반환합니다.
- **SC-002**: 추세 분석 예측치는 데이터가 일관적일 때 합리적인 오차 범위(선형 회귀 모델에 의해 정의됨) 내에 있어야 합니다.
- **SC-003**: 시스템은 데이터 파싱 실패 시 명확한 오류 피드백을 제공합니다(유효하지 않은 파일 100% 감지).

## 가정

- Obsidian 데이터 형식(`YY.MM.DD 억`)은 일관되고 올바르다고 가정합니다.
- 과거 데이터는 선형 회귀 분석을 수행하기에 충분합니다(최소 3개 데이터 포인트).
- 대시보드는 단일 사용자, 로컬 사용 전용입니다(다중 사용자 인증 불필요).
